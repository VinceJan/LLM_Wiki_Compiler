## 一、产品定位

**一句话定义**：可视化的 LLM Wiki 编译器 —— 让知识编译过程可见、可操作、可交互。

**核心价值主张**：
- 拖入文件/URL → 自动编译成结构化互链知识库
- 实时看到知识是如何被组织、连接、生长的
- 一次编译，反复查询，知识持续增值

**目标用户**：
- 有大量散落笔记/文档的知识工作者
- 研究者、写作者、技术博主
- 需要管理项目文档/技术知识的开发者

## 二、产品形态

### 2.1 整体布局

```
┌──────────────────────────────────────────────────────────────────────┐
│                    LLM Wiki Compiler                                 │
├────────────┬──────────────────────────┬──────────────────────────────┤
│  📥 输入区  │     ⚙️ 编译状态区         │       🗺️ 知识图谱区          │
│            │                          │                              │
│  [拖放文件] │  Ingest 进度指示器        │   力导向图可视化              │
│  [粘贴URL] │  正在生成: concepts/x.md  │   节点 = wiki 页面            │
│  [手动输入] │  已更新: index.md         │   连线 = [[wikilink]]         │
│            │  发现 5 个新概念           │   枢纽页高亮显示              │
│            │  断链检测: 2 个            │   孤立页警告                  │
│            │                          │   点击节点 → 查看页面内容      │
│  操作按钮:  │                          │                              │
│  [▶ Ingest] │                          │                              │
│  [💬 Query] │                          │                              │
│  [🔍 Lint]  │                          │                              │
├────────────┴──────────────────────────┴──────────────────────────────┤
│                        💬 Query & Lint 面板                           │
│  [输入问题] → 答案自动存为 Wiki 页面                                   │
│  [运行 Lint] → 断链/矛盾/孤儿页 检测报告                               │
└──────────────────────────────────────────────────────────────────────┘
```

### 2.2 三个核心面板

#### 面板 1：输入区（左侧）
- **文件拖放**：支持 PDF、Word、Excel、Markdown、TXT
- **URL 粘贴**：输入网页链接，自动抓取内容
- **操作按钮**：
  - `▶ Ingest`：摄入新内容
  - `💬 Query`：向知识库提问
  - `🔍 Lint`：健康检查

#### 面板 2：编译状态区（中间）
- **实时进度**：显示 Claude 正在执行的操作
- **文件变更列表**：创建/修改了哪些 wiki 页面
- **概念发现**：提取了多少新概念、更新了多少关联
- **统计信息**：总页面数、总链接数、断链数

#### 面板 3：知识图谱区（右侧）
- **力导向图**：D3/force-graph 可视化
- **节点** = wiki 页面（大小 = 链接数量）
- **连线** = [[wikilink]] 关系
- **交互**：
  - 点击节点 → 查看页面内容
  - 拖拽节点 → 调整布局
  - 搜索节点 → 快速定位
  - 颜色编码 → 概念页 / 实体页 / 摘要页

### 2.3 Query & Lint 面板（底部）

#### Query 模式
```
用户输入: "Transformer 和 RNN 的区别是什么？"
         ↓
LLM 搜索相关 wiki 页面 → 综合回答
         ↓
答案自动存为 wiki/queries/transformer-vs-rnn.md
         ↓
图谱中出现新节点
```

#### Lint 模式
```
运行 Lint → 扫描整个 wiki/ 目录
         ↓
检测报告:
  - 断链: 3 个 [[wikilink]] 没有对应文件
  - 矛盾: 2 个页面有冲突的陈述
  - 孤儿: 1 个页面没有被任何其他页面链接
  - 建议: 可以为 "MCP" 概念创建独立页面
         ↓
一键修复 / 逐个处理
```

## 三、用户操作流程

### 3.1 核心用户流程

```
Step 1: 用户拖入一篇 PDF 文章
         ↓
Step 2: 系统提取文本 → 存入 raw/article-001.md
         ↓
Step 3: 用户点击 "▶ Ingest"
         ↓
Step 4: 中间面板显示编译动画
         - "正在读取源内容..."
         - "发现概念: Transformer, Attention, RNN..."
         - "创建 wiki/concepts/transformer.md"
         - "创建 wiki/concepts/attention.md"
         - "更新 wiki/concepts/rnn.md"
         - "更新 wiki/index.md"
         - "记录到 wiki/log.md"
         ↓
Step 5: 右侧图谱实时更新
         - 新节点亮起
         - 新的连线出现
         - 枢纽页高亮
         ↓
Step 6: 用户点击图谱中的 "Transformer" 节点
         - 左侧弹出页面内容
         - 显示来源归因
         ↓
Step 7: 用户在底部面板提问
         - "Transformer 相比 CNN 有什么优势？"
         - LLM 基于 wiki 内容回答
         - 答案自动保存为新页面
         ↓
Step 8: 用户点击 "🔍 Lint"
         - 运行健康检查
         - 显示断链/矛盾/孤儿页报告
         - 一键修复
```

## 四、技术架构决策

### 4.1 后端：Claude Code CLI vs Claude API

| 维度 | Claude Code CLI | Claude API |
|------|-----------------|-----------|
| 文件操作 | ✅ 内置 | ⚠️ 需定义 tool |
| 多格式处理 | ✅ 内置 | ⚠️ 需外部库 |
| Agent 循环 | ✅ 自动 | ⚠️ 需 toolRunner |
| 用户门槛 | 需 Claude Code 环境 | 仅需 API Key |
| 流式输出 | ✅ 支持 | ✅ 支持 |

**决策**：✅ 方案 A 已验证可行（2026-04-11），作为首选后端。需设置 `CLAUDE_CODE_GIT_BASH_PATH=E:\Develop_tools\Git\bin\bash.exe`。方案 B 作为降级备选。

### 4.2 前端技术栈

| 层 | 技术 | 理由 |
|---|------|------|
| 框架 | Next.js + React | 快速构建、生态成熟 |
| 图谱 | force-graph (D3) | 力导向图可视化 |
| 状态 | React Context | 简单场景够用 |
| 样式 | Tailwind CSS | 快速开发 |

### 4.3 后端技术栈

| 层 | 技术 | 理由 |
|---|------|------|
| 框架 | Python FastAPI | 轻量、异步、好写 |
| LLM | 用户本地 Claude Code | 最强泛化能力 |
| 文件解析 | pdf-parse, python-docx, openpyxl | 成熟开源库 |
| 内容提取 | Jina Reader API | 免费、一行代码 |

## 五、差异化竞争

### 5.1 与现有方案的对比

| 方案 | 交互方式 | 可视化 | 内容摄入 | 用户门槛 |
|------|---------|--------|---------|---------|
| Claude Code CLI | 终端对话 | ❌ 无 | ✅ 内置 | 高（需订阅+CLI） |
| Obsidian + 插件 | 编辑器内 | ✅ Graph View | ⚠️ 手动 | 中（需装 Obsidian） |
| CacheZero | CLI + Chrome 扩展 | ❌ 无 | ✅ 扩展 | 中 |
| AnythingLLM | 桌面应用 | ❌ 无 | ✅ 内置 | 低 |
| **我们** | **Web UI** | **✅ 实时图谱** | **✅ 自动** | **低** |

### 5.2 核心卖点

1. **开箱即用**：无需安装 Claude Code / Obsidian / 任何 CLI
2. **可视化编译过程**：亲眼看到知识是如何被组织的
3. **知识图谱驱动**：不是被动浏览，而是主动探索知识网络
4. **多格式支持**：PDF、Word、Excel、网页、Markdown 全部支持
5. **自修复**：断链检测、矛盾检测、自动补全
